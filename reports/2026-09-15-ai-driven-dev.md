# AI駆動開発の動向レポート（2026-09-15）

## 総論：確率的な知能を、決定論的な仕組みで囲い込む

- この日の議論を貫くのは、「LLMは確率的にふるまう部品であり、その周囲を決定論的なソフトウェアで固めることで初めて実務に耐える」という発想の共有だ。`Deterministic Software + Probabilistic Intelligence` はこの構図を正面から扱い、確率的な出力そのものを改善するより、入出力の境界を設計する方が投資効率が高いと論じている。
- 実際、規約・権限・検証・評価・コストという各レイヤーの記事が、いずれも「モデルを賢くする」話ではなく「モデルの周りの構造を作る」話に収束している。プロンプト工夫の時代から、運用アーキテクチャの時代への移行が明確に見て取れる。
- 裏を返せば、エージェント単体の性能差は差別化要因として相対的に後退しつつある。組織が競うのは、同じモデルをどれだけ安全かつ安価に回せる土台を持っているかになってきた。

## チーム開発における規約とルールの実効性

- `AI エージェントとのチーム開発110日：規約は AGENTS.md だけでは足りなかった` は、エージェント向けの規約ファイルを置くだけでは統制が効かなかった実践記録である。ファイルは「読まれることを期待する静的な文書」にすぎず、遵守を保証する仕組みが別途必要だったという指摘は重い。
- 同記事が示すのは、規約をLint・CI・フックといった強制力のある経路に翻訳する必要性だ。人間の開発者に対しては機能する「ドキュメントによる合意」が、エージェント相手には機能しにくいという非対称性が浮かび上がる。
- 110日という期間の観察であることも価値が高い。短期の成功事例ではなく、運用が続いた先で何が摩耗するかを記録した知見として参照価値がある。

## 権限設計と「実行させない」アーキテクチャ

- `Claude Code の6つの許可モードを「誰が承認するか」で理解する` は、許可モードを機能一覧としてではなく「承認主体」という軸で整理し直した点が実務的である。Plan モードから始める段階的な導入手順と、Codex の権限設計との比較まで踏み込んでいる。
- 権限を「何ができるか」ではなく「誰が責任を持つか」で捉える視点は、組織へのエージェント導入時のガバナンス議論と直結する。ツール固有の設定の話が、そのまま内部統制の話につながっていく。
- より踏み込んだ提案が `【第1回】AIエージェントに実行させない——身体と頭脳の分離` だ。判断を下す「頭脳」と、実際に副作用を起こす「身体」を分離し、エージェントには実行権限そのものを与えないという構成を示す。
- この分離は、権限モードの粒度を細かくしていく方向とは異なるアプローチである。細かく許可を刻むのではなく、危険な操作の実行経路をアーキテクチャレベルで断つ設計思想として注目に値する。

## 品質保証：レビューと検証の作り直し

- `AIレビューの本番導入 — 人の承認を待つPRをどう絞るか` は、AIレビューを「全PRに適用する補助」ではなく「人間の承認が必要なPRを絞り込むフィルタ」として位置づけている。レビュー工数のボトルネックを直接狙う設計だ。
- 重要なのは、AIレビューの精度を上げることよりも、人間の注意をどこに配分するかという問題として定式化している点である。本番導入という文脈で語られているため、理想論ではなく運用上のトレードオフが読み取れる。
- 検証側では `AIエージェントの動作確認を「curlの200 OK」から「画面の視認」へ拡張した話` が示唆に富む。HTTPステータスが正常でも実際の画面が壊れているケースは多く、エージェントが自己申告する「完了」の信頼性を問い直している。
- エージェントが自分の成果を自分で検証する構造には原理的な限界があり、検証手段をより出力に近い層へ押し下げる動きは今後さらに広がると見られる。

## 評価指標とコストの現実

- `実際の企業コードでAIモデルの性能を測る「Real-SWE」とは？` は、公開OSSリポジトリ中心の既存ベンチマークが実務のコードベースを代表していない問題を扱う。学習データへの混入や課題の性質の偏りを避け、実企業コードで測る試みである。
- ベンチマークのスコアと現場の体感が乖離する経験は多くの開発者が持っており、評価基盤そのものを作り直す動きは導入判断の質を左右する。モデル選定の根拠として、公開スコアをそのまま信じない姿勢が広がりつつある。
- コスト面では `AI Agent時代の「トークン爆発」をどう防ぐ？ ～ NVIDIA研修より` が、エージェントの自律的な試行錯誤がトークン消費を非線形に膨張させる構造を整理している。エージェント化が進むほど、消費量の予測可能性が失われる点が本質的な課題だ。
- `マルチテナント環境におけるプロンプトキャッシング戦略` は、その対策を具体的なシステム設計として示す。テナントごとに異なるコンテキストを扱いながらキャッシュヒット率を確保する構成は、SaaSでLLM機能を提供する事業者にとって直接的な設計指針になる。
- 評価とコストが同時に論点化しているのは、AI駆動開発が実証実験段階を越えて、投資対効果の説明責任を問われる段階に入ったことの表れといえる。

## 利用者層の拡大

- `非エンジニアのPMがClaude Code × MCPで週次レポートを自動生成するまでの全手順` は、コードを書かない職種がコーディングエージェントを業務自動化ツールとして使う事例だ。MCPによる外部連携が、この裾野拡大の技術的な支えになっている。
- コーディングエージェントが「コードを書く道具」から「手順を実行する汎用的な道具」へと位置づけを変えつつあることを示す一例である。同時に、非エンジニアが権限を持つ実行環境を扱うことになるため、前述の権限設計や実行分離の議論の重要性が一段と増す。
