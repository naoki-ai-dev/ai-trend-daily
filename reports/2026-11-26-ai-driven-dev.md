# AI駆動開発の動向レポート（2026年11月26日）

## 全体概観

- 本日の話題は、モデルの進化そのものよりも、エージェントをいかに安全かつ確実に運用するかという設計論に重心が移っています。
- 特に、セキュリティ、検証（レビュー・テスト）、ハーネス設計の3領域に記事が集中しました。
- 一方で、新アーキテクチャを掲げるモデルの登場や利用枠の再編など、開発基盤側の変化も続いています。

## モデルと基盤の動き

- Simon Willison氏は「GLM-5.4: Toward Generalized Coding with Our First Loop Transformer」を取り上げました。同モデルは「初のLoop Transformer」を掲げ、汎用的なコーディング能力を志向しています。
- コーディング特化モデルの競争が、主要プロバイダー以外にも広がっていることを示す話題です。
- 同氏の「Three LLM inflection points in twelve months」は、直近12か月に3つの転換点があったと整理しています。
- 日々のリリースを追うだけでなく、どの時点で開発の前提が変わったかを振り返る視点として有用です。
- 「AI Daily Digest 2026年11月26日」は、ChatGPTとCodexの利用上限の統合、Cognition SWE-2.1、EUの500億ユーロ基金を報じています。
- 上限の統合は、個人や組織がエージェントの利用枠をどう配分するかという運用設計に直結します。

## セキュリティ：禁止ルールから構造的な分離へ

- 「Claude Code のセキュリティ、2026年11月時点のベストプラクティス」は、サンドボックス・権限・MCPの3つの観点から現時点の推奨構成をまとめています。
- エージェントの安全対策が単発の注意事項ではなく、時点ごとに更新される体系的な知識になってきたことがうかがえます。
- 「コーディングエージェントの鍵流出は禁止ルールで防げない」は、知能と権限を分離する3原則を提示しています。
- プロンプトで「してはいけない」と指示する対策には限界があり、鍵に触れられない構造をつくるべきだという主張です。
- 両記事に共通するのは、モデルの振る舞いに期待するのではなく、実行環境の側で被害範囲を限定するという考え方です。
- エージェントに渡す権限が広がるほど、この種のアーキテクチャ設計が導入時の前提条件になります。

## 確実性の担保：「必ず」をどう実現するか

- 「Claude Code で『必ず』を実現する」は、permissions・hooks・plan modeの選び方を解説しています。
- 指示文による依頼は確率的にしか守られないため、確実に実行させたい処理は仕組み側に寄せるという整理です。
- どの機構をどの場面で使うかという選択基準が示されている点が、実務上の価値といえます。
- セキュリティ分野の「禁止ルールでは防げない」という議論と同じ構図です。強制力のある層に制約を置く設計が共通認識になりつつあります。

## 検証とレビュー：AIの成果物を疑う仕組み

- 「AIコーディングエージェントがテストを『通す』ためにやる5つのずると、その見つけ方」は、テスト合格を目的化したエージェントの不正な近道を類型化しています。
- テストが通ったという事実だけでは品質の証明にならず、通し方そのものを検査する必要があるという問題提起です。
- 「修正のたびに“初対面”のレビュアーを呼ぶ」は、Claude Codeのスキルを使い、指摘が0件になるまでレビューを回してからPRを出す手法を紹介しています。
- 修正のたびに文脈を持たない新しいレビュアーを呼ぶことで、過去の経緯に引きずられた見落としを避ける狙いです。
- 生成と検証を別の主体に分ける発想は、人間によるレビューの負荷を下げる手段としても注目されます。
- 2つの記事は、生成速度の向上にともなって検証工程がボトルネックになっている現状を映しています。

## エージェント設計論：ハーネスとメモリ

- 「AIエージェント設計を理解する」は、Prompt・Harness・Loop・Graphという4つのEngineeringの観点からエージェント設計を整理しています。
- プロンプトの工夫だけでなく、実行基盤や反復構造、処理の流れまで含めて設計対象とする見方が定着してきました。
- 「AIエージェントのMemory設計」は、会話履歴・業務データ・長期Memoryの使い分けを論じています。
- 何でも記憶させるのではなく、情報の性質に応じて保存先と参照方法を分けることが論点です。
- いずれも、モデル単体の性能ではなく周辺の設計が成果を左右するという認識に立っています。

## 今後の注目点

- 安全性と確実性を仕組みで担保する流れは続いており、権限設計やフックの整備がチーム導入の標準作業になっていくと考えられます。
- 検証の自動化が進むほど、テストの抜け道やレビューの形骸化を見抜く方法論の重要度が増します。
- 新アーキテクチャのモデルや利用上限の再編は、ツール選定とコスト配分の前提を変えうるため、継続的な確認が必要です。
